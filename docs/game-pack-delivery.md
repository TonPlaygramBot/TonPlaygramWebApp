# TonPlaygram game-pack delivery

TonPlaygram now has a versioned game-pack layer on top of the existing Capacitor and PWA shells. The default build remains a complete fallback, while an opt-in **native-lite** build can bundle the core launcher and download validated heavy game assets from a CDN.

## Included architecture

- `webapp/scripts/generate-game-pack-manifests.mjs` scans selected runtime asset directories before Vite and adds a shared executable-runtime pack from the built output after Vite.
- Every release manifest contains the cache URL, download URL, byte size and SHA-256 digest of each file. The pack version is derived from the complete sorted file set.
- `webapp/src/pwa/gamePackManager.js` installs packs with bounded concurrency, cancellation, resume support, dependency handling, persistent-storage requests, atomic activation, eviction reconciliation and per-pack removal.
- Unchanged assets are copied from the previous versioned cache when their stored digest matches, so updates fetch only changed files.
- Small files are SHA-256 checked in the client. Large files are streamed to Cache Storage and checked against their generated byte size to avoid doubling mobile memory use.
- `webapp/src/pwa/gamePackFetchInterceptor.js` serves completed pack caches before the network. Staging caches are excluded until their completion marker is written, and `no-store`/`reload` requests bypass installed copies in both the page and workers. This is important inside Capacitor, where service-worker availability differs by operating system and WebView.
- `webapp/public/pwa/game-pack-service-worker.js` protects versioned pack caches when the app-shell service worker cleans old shell caches and makes worker-side fetches pack-aware.
- `webapp/src/pwa/gamePackRouteGuard.js` prevents a core-only native build from opening a managed game before its pack cache exists. Direct links are returned to the Games Lobby with the required pack focused and the original route preserved.
- Every Games Lobby card has a download-management link. The portrait-first manager provides install, resume, update, cancel, remove, dependency progress and storage information. In native-lite builds, game cards become download actions until their pack is available.
- Existing PWA warmup now skips managed heavy-game roots, so opening the browser fallback no longer silently downloads every large GLB before the player chooses a game.
- The first native-lite release only extracts fetch-safe 3D/binary data (`.glb`, `.gltf`, `.bin`, KTX2/Basis, DDS, HDR/EXR, JSON and WASM). Images, audio/video, standalone HTML/JS/CSS and other DOM-loaded media remain in the core shell until native filesystem-backed URL routing is certified on both Android and iOS.

## Generated packs

Every one of the 17 Games Lobby entries resolves to a pack. The larger shared groups remain:

- Tirana Streets
- Racing Royal
- Pool & Snooker Royale
- Table Tennis & Tennis Royal
- Royal Lanes Bowling
- Each other catalog game has its own pack, with a hidden shared table-game resource dependency.
- A hidden shared Tirana vehicle dependency is used by Tirana Streets and Racing Royal.
- After Vite, a hidden shared runtime dependency includes the built index and hashed JavaScript/CSS/font files for all visible packs.

Cross-game cast models (`chess-human.glb`, both athlete models and the shared Tirana soldier) are included in the shared table-game pack and remain in the core shell. Public media and game entry files are downloadable but are also retained in native builds. Downloadable files marked `nativeRemovable: false` must never be removed by the native-lite pruner.

Definitions are in `webapp/src/pwa/gamePackDefinitions.js`, shared by generation and the browser fallback. New catalog games automatically get a pack; declare any extra public asset roots, direct entry files or dependencies there. Downloading these packs does not export individual APKs or guarantee offline access to accounts, matches or dynamic network-only assets.

## Standard build

The standard build keeps all current public game assets inside `dist`, so Android/iOS remain fully self-contained while the pack manager provides persistent repeat-load and offline caching:

```bash
npm --prefix webapp run generate:game-packs
npm --prefix webapp run build
npm --prefix webapp run native:sync
```

Generated public-asset manifests are written to `webapp/public/pwa/game-packs/` and are intentionally ignored by Git. The normal build regenerates them after imported assets have been verified, then writes the final manifests including shared executable runtime into `dist/pwa/game-packs/`.

## CDN and core-only native build

Upload the same selected runtime files to an HTTPS CDN with their existing relative paths, then build the compact native shell:

```bash
GAME_PACK_CDN_BASE_URL=https://cdn.tonplaygram.com/game-packs \
  npm --prefix webapp run native:sync:lite
```

The native-lite pipeline does the following:

1. Compiles the app with `VITE_REQUIRE_GAME_PACKS=true`.
2. Generates manifests whose removable binary assets point to the CDN while the original local URLs remain cache keys. Core media and executable runtime keep their local source URLs.
3. Verifies every removable file has an HTTPS CDN source.
4. Removes only manifest-owned fetch-safe 3D/binary files from `dist` after the web build; DOM-loaded media and game entry code stay bundled.
5. Preserves pack cover art, the launcher, manifests and core UI.
6. Writes `dist/pwa/game-packs/native-prune-report.json` with removed file and byte totals.
7. Runs `cap sync` only after the guarded core-only output has been produced.

Android helpers are also available:

```bash
GAME_PACK_CDN_BASE_URL=https://cdn.tonplaygram.com/game-packs \
  npm --prefix webapp run android:sync:lite

GAME_PACK_CDN_BASE_URL=https://cdn.tonplaygram.com/game-packs \
  npm --prefix webapp run android:debug:lite
```

The CDN must provide CORS access and the exact bytes used when the manifests were generated. Immutable cache headers are recommended. Do not reuse an asset URL for different bytes without regenerating manifests.

## Release boundary

The standard native build remains the safe default. The native-lite command is intentionally opt-in and refuses to prune assets unless `GAME_PACK_CDN_BASE_URL` is HTTPS. Before distributing a lite APK/AAB or iOS archive:

1. Upload the exact generated asset set to the CDN.
2. Validate install, cancellation, resume, update, removal and storage pressure on physical Android and iOS devices.
3. Confirm each game’s cover and fallback thumbnail remains visible before download.
4. Exercise direct links and multiplayer invitations into every managed game.
5. Compare the prune report with the final APK/AAB or IPA size report.

KTX2/Basis, Draco/Meshopt and game-specific LOD conversion remain asset-production steps. The delivery layer already recognizes and versions those formats, but source models should be converted and visually certified game by game rather than modified indiscriminately during packaging. Moving the remaining images, audio and standalone game entry files out of the core bundle is a separate phase that requires a native filesystem-backed resource resolver and physical-device certification.
